# Структурное логирование

## Формат

### JSON-строки

Каждая запись — одна JSON-строка с фиксированным набором полей:
`ts`, `level`, `msg`, `service`, плюс поля события. Разбор без
регулярных выражений — главное преимущество перед человекочитаемым
форматом.

### Уровни

DEBUG для разработчика, INFO для бизнес-события, WARN для
автовосстановленной аномалии, ERROR для потери данных или запроса.
Не существует «ERROR для внимания»: уровень — это решение о
дальнейшей обработке, а не настроение.

## Контекст запроса

### Корреляция

`trace_id` проходит через все сервисы одного пользовательского
запроса; `span_id` разделяет участки внутри сервиса. Без корреляции
поиск причины размазывается по N лог-хранилищам.

### Поля безопасности

В лог не попадают пароли, токены и персональные данные: маскирование
делается в библиотеке логирования, а не призывом в код-ревью. Идентификатор
пользователя логировать можно, его email — нет.

## Хранение и стоимость

### Сэмплирование

Успешные запросы логируются сэмплированно (1 из 100), ошибочные —
всегда. Обратное сэмплирование ошибок недопустимо: редкая ошибка —
самая важная.

### Ретенция

Горячий индекс — 7 дней, тёплый — 30, архив — год в объектном
хранилище. Стоимости лог-системы растут линейно с объёмом, поэтому
ретенция — это решение о деньгах, а не о дисках.
