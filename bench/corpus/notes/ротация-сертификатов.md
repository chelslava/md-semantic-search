# Ротация сертификатов и секретов

## Жизненный цикл секрета

### Инвентаризация

Ротировать можно только то, что внесено в реестр: для каждого секрета —
владелец, срок действия, места использования. Секрет без владельца —
кандидат на немедленный отзыв.

### Сроки

Клиентские сертификаты — 90 дней, API-ключи — 180, корневые — годы.
Короткий срок означает частую автоматическую ротацию, длинный —
большой ущерб от утечки. Компромисс фиксируется политикой, а не
привычкой.

## Процедура ротации

### Двойной ключ

Ротация без простоя — выпуск нового секрета и работа с двумя
параллельно: пишут оба, читают новым, затем старый отключается.
Одношаговая замена «выпустить-удалить» гарантированно ломает хотя бы
один сервис, который не успел перечитать конфиг.

### Проверка после замены

После каждого шага — проверка реального доступа, а не «сервис
запущен»: запрос с новым ключом к живому эндпоинту. Мониторинг
ошибок авторизации в течение часа после ротации обязателен.

## Автоматизация

### ACME для TLS

Для TLS-сертификатов ротация автоматизируется через ACME: агент
сам выпускает и перевыпускает сертификат. Ручной процесс остаётся
только для корневых и промежуточных удостоверяющих ключей.

### Хранилище секретов

Secrets manager хранит версии, выдаёт по короткоживущим токенам и
пишет аудит. Передавать секреты через переменные окружения можно
только если окружение не видно дочерним процессам чужого пользователя.
